# حكيم — HAKIM NEXT Android

تطبيق أندرويد محلي مبني ليكون واجهة التنفيذ الميداني لحكيم مع الحفاظ على آخر Baseline موثوق.

## المبادئ الحاكمة

- مجاني أو مشمول فقط افتراضيًا؛ لا Credits ولا Metered تلقائيًا.
- الحقيقة قبل الادعاء؛ نجاح CI لا يساوي نجاح الهاتف.
- كل شيء×٨ لمنع سقوط أي بعد مادي.
- كيف×٧ لانضباط طريقة التنفيذ.
- الحكمة×٧ لاختيار الفعل الأنسب والأقل ندمًا.
- الابتكار×٧ لتوسيع الحلول دون تغيير لمجرد الجِدّة.
- لا كلمات مرور أو OTP أو مفاتيح API في المهام العامة.
- الأفعال عالية الأثر عن بُعد مرفوضة في هذا الإصدار.
- Accessibility لا يُفعّل تلقائيًا؛ يفعّله المستخدم من إعدادات أندرويد.
- الروابط الخارجية محصورة في HTTPS ونطاقات مسموحة.

## ما يفعله الإصدار ٠٫١٫٠

- واجهة عربية RTL واضحة للحالة والتشغيل والإيقاف والفحص.
- فتح ChatGPT وGemini خارجيًا دون WebView أو تخزين جلسات تسجيل الدخول.
- جلب مهمة عامة غير حساسة من GitHub عبر HTTPS فقط.
- بوابة تكلفة Fail-Closed: `FREE` و`INCLUDED` فقط.
- تنفيذ محلي محدود: فتح رابط، انتظار، إدخال نص غير سري، نقر نص غير عالي الأثر، تحقق نصي، حالة، تقرير منقح.
- تقييد Accessibility إلى Firefox وChrome وتطبيق Google فقط.
- حفظ حالة التنفيذ محليًا مع منع إعادة المهمة المنجزة.

## البناء

يُبنى APK آليًا في GitHub Actions عبر `.github/workflows/hakim-android-apk.yml` باستخدام Java 17 وAndroid 35 وGradle 8.9. مخرج التطوير هو `app-debug.apk`، ويُحفظ كـArtifact في تشغيل الـWorkflow.

## معيار الترقية

لا يصبح التطبيق هو «حكيم الأصلي الوحيد» لمجرد أن APK بُني. يجب أولًا:

1. اجتياز الاختبارات وAPK build على نفس الرأس.
2. تثبيت APK على الهاتف الحقيقي.
3. منح Accessibility محليًا من المستخدم.
4. نجاح مهمة Smoke مجانية مرتبطة بمعرّف mission_id.
5. وصول دليل ميداني منقح أو فحص بصري مباشر.
6. عدم وجود P0 regression مقارنة بآخر Baseline مثبت.

حتى ذلك الحين يبقى التطبيق `CANDIDATE / FIELD_UNQUALIFIED`، ويبقى حكيم الحالي هو Baseline الرجوع.
